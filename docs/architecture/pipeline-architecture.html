Pre-Embedding Risk Gate

Raw candidate chunks are isolated outside the searchable vector set until automated inspection rules verify table integrity, schema compliance, and tenant ownership.

LLM-Free Retrieval

Zero generation latency on the backend server. The pipeline extracts, ranks, and returns verifiable chunks directly to Claude Desktop / Code to synthesize answers.

Tenant Isolation

Enforced via mandatory X-AMC-Scope HTTP header. Multi-tenant partitioning guarantees AMC data segregation and audited regulator access (RTA).

⚠️ Fail-Closed Ingestion Contract
Candidate chunks and rule violation findings are stored outside the searchable vector set. A malformed chunk or extraction table anomaly cannot reach retrieval before inspection and review approval.

Sequential Pipeline Stages

DISCOVER & FETCH
Coordinated via discovery_runs with distributed PostgreSQL leases. Verifies cryptographic hashes to avoid duplicate processing.
PARSE & CHUNK
Extracts tables, sections, footnotes, and metadata from Scheme Information Documents (SID), KIM, and Factsheets.
DETERMINISTIC INSPECTION
Validates tenant ownership, parser drift, chunk boundary stability, and mandatory disclosure presence.
HUMAN AUDIT & RELEASE
Reviewers can view side-by-side context and edit candidate chunks at /review. Editing automatically reinspects the document.

RRF & Ranking Formulation

Candidates from dense vector search and full-text lexical search are merged using Reciprocal Rank Fusion:

RRF Score = 1 / (k + Rank_dense) + 1 / (k + Rank_lexical)
Default parameter: k = 60

Document priority weights adjust scores to prioritize recent addenda and monthly factsheets over older annual SIDs when querying dynamic facts (NAV, AUM, fund manager updates).

Hugging Face TEI Reranking

Top 20 fused candidates pass to BAAI/bge-reranker-v2-m3 running on Hugging Face Text Embeddings Inference:

  • Cross-Attention: Evaluates query-chunk pairs jointly for semantic precision.
  • Section Header Context: Prepends section headers to preserve document hierarchy.
  • Fail-Safe Fallback: If the reranker is unavailable, retrieval transparently falls back to RRF rank order.

Architectural Rationale: Why LLM-Free?

Traditional RAG pipelines rely on small local generative models (e.g., 7B parameters) to generate answers. In financial mutual fund compliance, local models often miss tabular details or hallucinate expense ratios. MF-RAG avoids this by returning high-precision chunks directly to Claude.

Metric With Local LLM (e.g. 7B) MF-RAG (LLM-Free Server)
Latency 8–16 seconds Sub-second retrieval + reranking
Table Accuracy Fails on complex financial tables & footnotes Parses tables into structured chunks; Claude synthesizes
Security Vulnerable to prompt injection & jailbreaking Zero backend LLM attack surface
Infrastructure Cost Heavy VRAM for local generative inference Self-hosted embedding + lightweight reranker
Audit Citations Unreliable or hallucinated page numbers Exact source URLs, filenames, and verified page numbers
💡 The Claude Advantage
Claude Desktop and Claude Code already excel at multi-step reasoning, mathematical verification, and tabular understanding. The MCP server feeds high-relevance chunks and citations, letting Claude generate safe, accurate responses.
